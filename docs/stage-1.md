# Stage 1 — Wire protocol

## Built
- `protocol/SPEC.md`: the 28-byte report, MQTT topics/session settings, SMS format, error codes.
- `protocol/test-vectors.json`: 11 reports, 5 bad reports, 3 SMS, 7 bad SMS. Generated by `protocol/js/gen-vectors.js`; the other languages must reproduce it exactly.
- `protocol/js` (`crc16, encode, decode, decodeBatch, smsEncode, smsDecode, ProtocolError`).
- `protocol/python` package `jeeptrack_protocol` (same API, snake_case, plus `decode_batch`).
- `protocol/kotlin` (`Report`, `Codec`, `ProtocolError`), a Kotlin/JVM Gradle project (wrapper 9.8.2, Kotlin 2.4.21, bytecode target 21).

## Run tests
```bash
(cd protocol/js && npm test)                                   # 33 pass
.venv/Scripts/python -m pytest protocol/python                  # 33 pass
(cd protocol/kotlin && ./gradlew test)                          # 8 test methods (all vectors) pass
```
Python setup: `python -m venv .venv && .venv/Scripts/pip install pytest -e protocol/python`.

## Known gaps
- Batch decoding exists in JS and Python only. Kotlin doesn't need it (the phone only encodes batches).
- The SMS timestamp window (15 min old / 2 min future) is checked by the server (Stage 8), not by the codecs.
